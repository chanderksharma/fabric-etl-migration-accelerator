Functional parity

1Compare schemas, data types, row counts and record-level reconciliation.
2Test nulls, expressions, joins, grouping and rejected-row behavior using edge cases.
3Validate every parameter combination and conditional route.

Operational acceptance

1Confirm identities, connections, permissions and environment configuration.
2Test retries, restart points, idempotency, logging and alerting.
3Measure runtime and capacity using representative production volumes.

Cutover and rollback

1Agree acceptance thresholds and business-owner sign-off.
2Run old and new implementations in parallel where practical.
3Retain a tested rollback route until parity is accepted.
This creates one or more Fabric items from a generated deployment bundle. Review and test every component before production use. SPN credentials and tokens remain only in page memory; secrets are cleared immediately after authentication and when the panel closes.

Deployment target

Existing workflow contract: the workflow must exist on the repository’s default branch and its workflow_dispatch trigger must accept workspace_id, deployment_name, component_count, and deployment_manifest_base64. The workflow should obtain its Fabric SPN from protected GitHub secrets and implement create/update, ID binding, retry and rollback controls.

GitHub token: use a repository-scoped fine-grained PAT with Metadata read and Actions write, or a GitHub App installation token. It is held only in page memory and cleared immediately after dispatch.

Direct deployment: creates new Fabric items and is not transactional. If a later component fails, successfully created components remain in the workspace and must be reviewed, retried or removed.

SPN prerequisites: enable “Service principals can use Fabric APIs” in Fabric tenant settings, include the SPN in the allowed security group, grant it Contributor or higher access to this workspace, and use a supported Fabric capacity.

Security: direct browser secret entry is suitable only for this prototype. Prefer GitHub Actions with protected secrets, workload identity federation, a certificate, or another secured CI/CD process.
